Root cause

Why recall returns noise — or nothing

Session-start recall asks the database for memories matching the current working directory. The FTS index includes repo_path, so the path matches every row in that repo. The top five are whatever the index returns first — almost always edit logs.

// src/ui/run-startup-tasks.ts:103 sessionStartRecallRef.current = manager.recall({ text: cwd, repoPath: cwd, limit: 5 }); // src/memory/db.ts:37 — repo_path is searchable CREATE VIRTUAL TABLE memories_fts USING fts5( content, category, repo_path, content='memories' );
Result: the cwd query matches 151 active rows in kimi-code and 111 in clone-1. The top five are all “File modified: …”. In autopilot it matches 0 rows, because the rows are still keyed to /Users/sinameraji/kimiflare after the rename.

High-leverage opportunities

What to fix, in order

Ranked by impact on whether memory actually helps. The first two are urgent: one makes the feature reachable, the other prevents the first enable from deleting the entire archive.

Turn it on — or make “off” explicit

P0
Memory is opt-in and nobody opted in. 0 of 116 traced sessions had it enabled. The model tried twice this week — a recall about a Node version decision and a preference about draft PRs — and both got “Memory is not enabled.” as a successful tool result. The README still advertises memory as a headline feature.
Fix: default memoryEnabled to true for the TUI (keep /memory off), or add a first-run prompt. Gate the memory tools and the system-prompt bullet on the flag. Return ok:false when disabled. Add a status-bar indicator.
Impact: highEffort: S
src/config.ts:377 · src/tools/executor.ts:50 · src/agent/system-prompt.ts:83 · src/tools/memory.ts:47

Don’t wipe the archive on first enable

P0
Cleanup deletes by age regardless of importance. The 90-day cutoff is 1 Aug 2026; every one of the 2,007 rows is older, including all 14 high-signal rows. Enabling memory today runs cleanup on startup and deletes 100% of the archive before recall can use it.
Fix: protect importance >= 4, instruction, and preference from age deletion. Run a dry-run/migration before the first cleanup. Make age deletion opt-in. Add a schema version and a backup step.
Impact: criticalEffort: S–M
src/memory/cleanup.ts:54 · src/memory/db.ts:365 · src/ui/run-startup-tasks.ts:81

Recall the task, not the path

P1
Session-start and resume recall use text: cwd. Because FTS indexes repo_path, the path matches every row in the repo; the top five are arbitrary edit logs. After the rename, autopilot matches 0 rows. The result is noise or nothing — never the instruction you actually need.
Fix: query with the first user message, session title, or recent high-signal memories. Scope FTS MATCH to the content column. Add an importance + recency prior. Exclude event rows from default recall.
Impact: highEffort: S–M
src/ui/run-startup-tasks.ts:103 · src/ui/use-session-manager.ts:369 · src/memory/db.ts:37 · src/memory/retrieval.ts:70

Give a repo a stable identity

P1
Memories are keyed by absolute cwd. The kimiflare → autopilot rename orphaned 269 memories (still keyed to /Users/sinameraji/kimiflare). Monorepo subdirs fragment (kimiflare-cloud/worker 0 vs kimiflare-cloud 45; glia/glia-core 20 vs glia 0). Autopilot’s own worktrees would each get a fresh DB.
Fix: resolve the git root / common dir or remote URL as the repo identity. Migrate old repo_path values. Use one DB per repo root, not per cwd. Normalize paths before storing.
Impact: highEffort: M
src/ui/run-startup-tasks.ts:66 · src/tools/memory.ts:60 · src/memory/manager.ts:208

Persist related_files

P1
Extractors return relatedFiles, but MemoryManager.remember() has no such parameter and drops them. 0 of 2,007 rows have files. That kills the exact-match retrieval channel and the supervisor’s pre-read file list.
Fix: add relatedFiles to remember() and insertMemory(); pass it from every extractor. Backfill from topic keys and paths. Use it in retrieval and in getPreReadFilesFromMemory.
Impact: med–highEffort: S
src/memory/extractors.ts:198 · src/memory/manager.ts:208 · src/memory/retrieval.ts:25 · src/agent/supervisor.ts:127

Cut extraction noise and cost

P2
Every edit/write triggers 5–7 model calls (synthesis, verifier, retry, verify, hypothetical queries, embedding). 80% still fall back to “File modified”. The verifier prompt assumes the memory was “explicitly provided by the user”, so it cannot reject auto-extracted noise. 72% of rows are superseded.
Fix: extract at session end or on explicit memory_remember. Skip tests, docs, lockfiles. Batch per file. Drop verify/hypothetical queries for deterministic extractors. Prompt for decisions and rationale, not diffs.
Impact: highEffort: M
src/agent/loop.ts:1652 · src/memory/extractors.ts:111 · src/memory/manager.ts:527

Fix topic keys and supersession

P2
In kimi-code, project_entry_point is shared by every entry point: 112 rows stored, 1 active. event_edit_<path> keeps one row per file. Relative vs absolute paths create different keys (271 duplicate content groups). Concurrent extraction races leave 41 topic keys with multiple active rows and 16 rows stuck at superseded_by = "pending".
Fix: per-path entry-point keys; session-scoped event keys; normalize paths; add a unique constraint and a transaction; don’t supersede events. Reserve supersession for facts and preferences.
Impact: med–highEffort: M
src/memory/manager.ts:238 · src/memory/extractors.ts:240 · src/memory/db.ts:421

Fix dead extractors and dead paths

P2
The read tool returns line-numbered text, so JSON.parse fails for the package_json and tsconfig extractors — 0 rows ever. memoryContext is never populated; recallByRole is unused; getPreReadFilesFromMemory is only called from tests; the continuation summary filters on "edit_event", which is not a category.
Fix: strip the line-number prefix before JSON.parse, or add a raw read mode for extractors. Remove or wire the dead paths. Fix the category filter to event.
Impact: mediumEffort: S

Fix: track whether a recalled memory was actually used; show memory health in the status bar; add IDs to recall output; add per-memory delete; add /memory doctor with recall hit rate and noise ratio.

What I changed

The audit's code-level fixes are implemented on the worktree branch, with focused tests. The product decisions — default-on, repo-identity migration, and extraction policy — are left for you.

Recall correctness
  • Session-start recall now queries with the user's prompt, not cwd.
  • Resume recall uses the session title; continuation summaries use the original goal.
  • FTS matches are scoped to the content column, so repo_path no longer matches every row.
  • Continuation-summary category filter fixed (event, not edit_event).
Data quality
  • related_files are persisted from extractors.
  • package.json / tsconfig extractors strip read-tool line numbers.
  • Entry points get per-path topic keys; edit paths normalize to repo-relative.
  • Age cleanup protects importance ≥ 4, instruction, and preference rows.
  • memory_recall output includes IDs so memory_forget works.
Verification

39 memory tests and 76 agent/tool tests pass. Typecheck is clean for every changed file; the worktree still has pre-existing aster-* / sandbox.ts errors from uncommitted work. Opened as PR #1066.

Method. Scanned 39 .kimiflare/memory.db files under $HOME (15 with data, 24 empty), 116 traced sessions in ~/.local/share/kimiflare/traces (Oct 2026), and 187 session files in ~/.local/share/kimiflare/sessions. Queried SQLite directly for counts, categories, importance, supersession, access times, topic keys, and duplicate content. Parsed trace.jsonl for session_start.config.memoryEnabled, tool_call/tool_result events, and recall-injection blobs. Read the memory subsystem at commit b49a2b5 (30 Oct 2026).
Caveats. Traces are retained for a limited window, so the April–July period is reconstructed from the DBs, not traces. “High-signal” = instruction, preference, or fact with importance ≥ 4. “Recalled” = accessed_at > created_at; this is a lower bound because recall updates only the top results. The 90-day cleanup projection assumes the default memoryMaxAgeDays of 90 and today’s date.
